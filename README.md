# 사료 판독 하네스: 생성형 인공지능을 활용한 근대 문헌사료 판독 실험 코드

본 저장소는 논문 「생성형 인공지능을 활용한 근대 문헌사료 판독 방법과 활용 조건 ― '사료 판독 하네스'의 제안과 조선총독부박물관 불국사 관련 문서의 사례 ―」(투고 중)의 실험 코드와 지시문, 집계 결과를 공개한다.

> 서지 정보와 인용 방법은 게재 확정 후 기재한다.

## 공개 범위

| 공개 | 비공개 |
|---|---|
| 1단계·2단계 실행 코드 | 원본 이미지 (국립중앙박물관 소장, 아카이브에서 열람 가능) |
| 실험에 쓴 지시문 3판 원문과 변경 내역 | 1단계 인식 결과, 2단계 재독해 결과 |
| 판독 실험 대상 서지 목록 (파일 ID 수준) | 기준 판독문 |
| 평가 지표 집계 결과 | |

판독 텍스트는 연구자가 원본과 전면 대조하여 확정하기 전에는 공개하지 않는다. 검증을 거치지 않은 판독 결과에는 원문에 근거하지 않은 내용이 표시 없이 섞여 있을 수 있으며(논문 Ⅵ장), 공개되면 사료의 내용처럼 인용될 수 있기 때문이다.

## 파이프라인

1. **1단계 문자 인식** (`stage1_vision.py`): Google Cloud Vision `DOCUMENT_TEXT_DETECTION`, 언어 힌트 `ja`, `zh-Hant`. 2026년 4월 20일에 한 번 산출한 결과를 모든 실험에 똑같이 입력하였다.
2. **2단계 문맥 재독해** (`run_experiment.py`): 원본 이미지와 1단계 결과를 지시문과 함께 Gemini에 입력한다.
3. **3단계 연구자 검증**: 연구자가 원본과 대조하여 교정한다(코드 없음).

## 지시문

| 공개 파일 | 논문 명칭 | 실험 당시 내부명 | MD5 앞 8자리 |
|---|---|---|---|
| `prompts/v1_initial.txt` | 초기 지시문 | v1 | `6bf22ffd` |
| `prompts/v2_revised.txt` | 수정 지시문 (확정본, 이후 실제 판독에 사용) | v3 | `57e7db87` |
| `prompts/v3_detailed.txt` | 상세화 지시문 | v4b | `938632bc` |

- 파일 내용은 모델에 보낸 원문 그대로이다. 상세화 지시문 본문에 남아 있는 "v4 보강", "v4 신규"는 실험 당시의 내부 작업명이며, 실험 원문을 보존하기 위해 고치지 않았다.
- 실험 당시 내부명 v2는 v1과 v3 사이의 작업본으로, 비교 실험에 쓰지 않았으므로 공개하지 않는다.
- `run_experiment.py`는 실행 전에 지시문의 MD5를 확인하여 원문과 다르면 실행하지 않는다. MD5는 파일을 UTF-8 텍스트로 읽은 값 기준이다.
- 판 사이의 변경 내역은 `prompts/README.md`와 `prompts/diff_*.diff`에 정리하였다.

## 실험 조건

| 항목 | 값 |
|---|---|
| 대상 | 불국사 관련 문서 [122]건 [279]면 (기준 판독문 20자 미만인 [26]면은 지표 계산에서 제외) |
| 지시문 | 3판 (v1·v2·v3) |
| 모델 | `gemini-2.5-flash` (google-generativeai 0.8.6), `gemini-3.8-flash` (google-genai 2.28.0) |
| 반복 | 조합마다 3회 (총 18개 조합 × 면 수) |
| 생성 설정 | temperature·top_p·top_k·안전 설정 지정 안 함 (기본값) |
| Gemini 3.8 추가 설정 | 사고 수준 `MEDIUM` (모델 기본값을 명시), 이미지 해상도 `MEDIA_RESOLUTION_HIGH` |
| 입력 구성 | `{지시문}\n\n[1차 원시 텍스트 (vision_raw)]\n{1단계 결과}` 문자열 + 원본 이미지 |
| 호출 순서 | 시드 `20260925`로 섞음, 동시 호출 5건 |
| 실행 시기 | [2.5-flash: 2026년 ○월 / 3.8-flash: 2026년 ○월] |

## 실행 방법

```bash
pip install -r requirements.txt
cp .env.example .env   # 키 입력

# 1단계
python stage1_vision.py --image-dir 이미지폴더 --out-dir 실험데이터/비전결과

# 2단계 (호출 수만 확인)
python run_experiment.py --sample 표본목록.csv --image-dir 이미지폴더 \
    --vision-dir 실험데이터/비전결과 --model gemini-3.8-flash --dry-run

# 2단계 본 실행
python run_experiment.py --sample 표본목록.csv --image-dir 이미지폴더 \
    --vision-dir 실험데이터/비전결과 --model gemini-3.8-flash
```

표본목록은 `파일id`, `상대경로`(`--image-dir` 기준), `분석집합`(`본 분석` 또는 `짧은 면`)의 세 열로 된 CSV이다. 원본 이미지는 국립중앙박물관 조선총독부박물관 문서 아카이브에서 받아 `상대경로`에 맞추어 두어야 한다.

## 평가

`evaluation/analyze.py`와 `evaluation/analyze_by_type.py`는 실험 당시 분석 코드의 공개본이다. 계산은 바꾸지 않았고, 경로를 인자로 받게 하고 지시문 이름을 공개명으로 바꾸었다. 코드 안의 "정답지"는 논문의 "기준 판독문"이다.

- `analyze.py`: 면마다 3회 평균을 낸 뒤 정밀도·재현율·F1·문자 정확도·Levenshtein 유사도를 구하고, 두 비교(v1→v2, v2→v3)를 면 단위 짝 비교로 검정한다(부트스트랩 95% 신뢰구간 10,000회, Wilcoxon 부호순위 검정, F1에 Holm 보정). 상세화 지시문에서 새로 추가된 어휘 36개의 복원·삽입 횟수를 함께 센다.
- `analyze_by_type.py`: 세 지시문을 줄 단위로 8가지 종류(맥락 제시, 근거 원칙, 전사 절차, 표기 규약, 규칙 예시, 구조 템플릿, 내용 어휘, 출력 형식)로 분류하고, 종류별로 겨냥한 모델 행동(신자체 오용, 〃 복원, 불확실성 표기, (鈐印) 표기, 양식 어휘 삽입 등)을 비교한다.

```bash
python evaluation/analyze.py --sample 표본목록.csv --gold-dir 기준판독문 \
    --results 실험데이터/출력/gemini-3.8-flash --out 실험데이터/분석결과/gemini-3.8-flash
```

기준 판독문은 공개하지 않으므로, 평가 코드는 계산 절차를 공개하기 위한 것이다. 하위·민감도 분석에 쓰는 열(`주범주`, `구분`, `판독문바탕`, `확인필요`)은 표본목록에 있으면 쓰고, 없으면 생략한다.


## 공개본과 실험 원본 코드의 차이

실험은 연구자의 로컬 환경에서 실행하였다. 공개본은 다음만 바꾸었다.

- 로컬 경로를 명령행 인자로 바꾸었다.
- 운영 기록용 엑셀 갱신, 내부 비용 기록 참조, 폴더 상시 감시 기능을 덜어 냈다.
- 지시문 이름을 공개명(v1·v2·v3)으로 바꾸었다. 파일 내용은 바꾸지 않았다.

모델 호출 방식, 입력 구성, 생성 설정, 반복 횟수, 시드는 원본과 같다.
